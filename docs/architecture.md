# 架构说明

## 宿主约束

notepad-- 的插件入口由两个 C 符号组成：

```cpp
bool NDD_PROC_IDENTIFY(NDD_PROC_DATA *data);

int NDD_PROC_MAIN(
    QWidget *notepad,
    const QString &pluginFilePath,
    std::function<QsciScintilla *(QWidget *)> getCurrentEditor,
    std::function<bool(QWidget *, int, void *)> hostCallback,
    NDD_PROC_DATA *data);
```

`NDD_PROC_IDENTIFY` 返回插件元数据和菜单类型。此插件使用 `menuType = 1`，因此宿主会先创建插件根菜单，再调用一次 `NDD_PROC_MAIN` 让插件注册子菜单。入口 ABI 来自 notepad-- v3.8.3 官方 Gitee 标签中的 `src/include/pluginGl.h` 和 `src/plugin.h`。本项目在 `src/ndd_plugin_api.h` 中保留相同的字段类型与顺序，包括末尾的 `QAction *`；两个回调也保留宿主要求的 `QWidget *` 参数。

## 组件关系

```text
notepad-- / CCNotePad
  ├─ 插件根菜单
  │    └─ PreviewController 注册 QAction
  ├─ editTabWidget 当前页 ──> HostAdapter ──> PreviewController
  │                              │              │ 调度与状态
  │                              │ Qt 元对象调用
  │                              v
  │                    ScintillaEditView::on_viewMarkdown
  │                              │ 宿主内部读取与更新
  │                              v
  └─ QMainWindow ─────── MarkdownView ──HostAdapter 解析──> QDockWidget
```

`HostAdapter` 是控制器可注入的最小宿主边界。默认 notepad-- 实现集中处理当前编辑器发现、
`filePath` 读取与变化识别、右键 Markdown 动作识别和断连、原生预览创建／刷新、预览内部
`QTextEdit` 解析、宿主窗口装饰隐藏、即时刷新连接移除及预览所有权协作。每次能力探测返回
明确成功状态、耗时或错误信息。`PreviewController` 只消费这些结构化结果并维护文档身份、版本、
调度和菜单状态；`MarkdownPreviewDock` 只接收已经解析的预览窗口与文本控件，负责嵌入、样式、
滚动、链接和导出，不再了解宿主对象名或窗口结构。

保存字体读取同样经过 `HostAdapter::savedMarkdownFont()`，默认适配器封装
`saved_markdown_font.*`；可注入用户配置根目录、宿主安装目录和读取结果，控制器与 Dock
均不自行访问配置。读取与缩放的完整边界见下文“保存字体与窗口缩放”。

默认适配器从宿主的 `editTabWidget` 取得当前页，并把标签 `currentChanged` 与当前编辑器
垂直滚动条的 `valueChanged`、`rangeChanged` 转换为宿主无关的状态变化通知。标签通知使用
零延迟单次计时器合并，待宿主当前事件返回后统一读取编辑器、路径和版本，兼容宿主先切换
标签、后设置动态属性的顺序。控制器只在 Dock 可见时运行 1500 ms 的低频轮询作为兼容兜底；
Dock 隐藏后停止轮询，重新显示时立即同步一次。插件监听文本变化并合并连续刷新，实际的
文本读取和 Markdown 解析仍由 notepad-- 完成。测试可注入不使用任何 notepad-- 对象名或
槽名的适配器，直接验证控制器状态与 Dock 展示行为；这类模拟测试不替代真实宿主 ABI 验证。

每个宿主窗口分别持有一个 `PreviewController`。插件入口在当前 `notepad` 的直接子对象中
查找控制器：同一窗口重复调用时复用已有实例，不重复注册菜单、计时器或事件过滤器；新窗口
则创建自己的控制器和 Dock。`MarkdownPreviewDock` 由对应宿主主窗口持有，使用
`QMainWindow::addDockWidget` 加入右侧停靠区。关闭任一宿主窗口时，Qt 的父子对象所有权只会
清理该窗口的控制器、Dock 和动作，不影响同进程中的其他窗口。

诊断设施按进程初始化且幂等，日志文件使用 `markdownview-<进程号>.log`，避免不同 notepad--
进程互相截断或混写。同一进程的每条记录包含进程号和稳定的 `window-N` 标识，以区分多个
宿主窗口；重复调用同一窗口入口只追加记录。单个日志上限为 1 MiB，超限后轮转并保留 3 份
历史文件。写入和轮转由进程内互斥保护，默认过滤 `Debug` 级高频跟踪，关键记录每次立即刷新；目录创建或文件打开失败时
静默放弃该条诊断，不影响插件功能。为减少路径信息暴露，编辑器路径只记录文件名和不可逆的
短路径摘要，应用程序只记录可执行文件名。

原生 `MarkdownView` 嵌入 Dock 后由 Dock 的 QWidget 父子关系持有；控制器仍保留编辑器
销毁时调用 `deleteLater` 的协作路径，以覆盖编辑器先关闭的情况。Dock 为当前及已经隐藏的
全部原生预览分别保存 `destroyed` 连接。普通预览关闭时仅在它仍是当前预览的情况下恢复
备用界面；Dock 析构开始时先停止布局计时器、断开滚动与全部预览销毁连接，再由 Qt 递归
删除子控件，避免派生类成员销毁后进入回调，也避免对同一预览重复删除。

每个宿主窗口的控制器最多缓存 3 份原生预览，并按最近使用顺序淘汰；当前活动文档始终保留。
切换文档前记录当前预览滚动比例，关闭同步滚动时，即使原生预览已被淘汰并由宿主重新创建，
也会在新文档布局后恢复该文档自己的阅读比例。淘汰只通过 `HostAdapter::releasePreview()`
执行：默认适配器先清除编辑器上的预览身份和当前状态属性，断开适配器安装的销毁协作连接，
再对预览调用 `deleteLater()`。notepad-- 自身使用 `QPointer<MarkdownView>`，对象销毁后指针自动
清空，返回该标签时 `on_viewMarkdown` 能创建新实例。Dock 已跟踪的 `destroyed` 回调负责移除
当前控件和滚动连接；关闭标签仍沿用编辑器销毁时释放预览的路径。容量 3 是用于限制对象数的
保守固定值，不代表已经完成真实宿主内存峰值测量。

曾经接入的编辑器保留轻量的文本变化与销毁监听，直到编辑器或控制器销毁；切换标签只解绑
当前编辑器的滚动监听。后台文档被宿主“替换所有已打开文档”等操作修改时，推进该文档的源码版本并使缓存失去
最新资格，不触发后台渲染；旧快照仍可阅读。返回标签后遵循窗口刷新模式，显式导出则取得
最新内容。缓存条目同时保存路径，
后台路径属性变化或重新接入时发现路径变化，也会使缓存失效。预览淘汰不移除这些轻量监听。

控制器同时监听编辑器临时创建的右键 `QMenu`，但只处理菜单、当前编辑器和自身宿主窗口
三者归属一致的事件。发现原生 Markdown 动作后，插件先断开它与编辑器原生预览槽的连接，
再检查文件类型、显示 Dock 并调用宿主槽渲染。原生预览创建后，插件按“`textChanged` 信号
到编辑器自身接收者”的范围清除宿主即时刷新连接；插件和主窗口是不同接收者，因此各自的
状态更新连接不受影响。每次文本变化还会重新检查该连接，防止宿主入口再次恢复逐键渲染。

显示／隐藏预览快捷键使用 `Qt::WindowShortcut`，仅在所属宿主窗口为活动窗口时生效，避免
同进程的多个控制器争抢应用级快捷键。

文本变化只重启一个单次计时器，连续输入期间不会渲染。计时器等待时间根据上一次渲染耗时在 350 ms 到 2 秒之间调整，随后只调用一次宿主 `on_updataMarkdown`。自动计时器触发时先核对编辑器身份和内容版本；预览已经是同一版本时直接跳过，因此显示 Dock、标签轮询和重复调度不会再次解析未变化内容。侧栏隐藏时会停止待执行的渲染。文件类型和路径检查发生在真正渲染时，不进入逐键输入路径。

### 刷新模式、保护状态与展示版本

`PreviewController` 按宿主窗口保存 `RefreshMode::Automatic/Manual`，初值为自动。
菜单的互斥动作和 Dock 的模式下拉框调用同一 `setRefreshMode()`；关闭／重开 Dock、换标签、
显式刷新及导出都不改变模式。此阶段只保存在内存中，不提供全局偏好落盘。

性能保护与用户模式分离。磁盘文件达到 1 MiB，或最近一次完整渲染达到 750 ms 时，
自动模式中的后续更新暂停。完整耗时按编辑器缓存；命中快照不覆盖该测量，普通文档不继承
慢文档状态。显式刷新后重新评估大小和耗时。自动模式的首次打开仍沿用允许渲染的现有策略，
手动模式首次打开则只提示刷新；未保存缓冲区规模和首次渲染耗时治理留给后续性能需求。

| 事件 | 状态与动作 |
| --- | --- |
| 自动模式编辑普通文档 | 推进源码版本，状态待刷新，重启 350～2000 ms 单次防抖 |
| 自动模式编辑受保护文档 | 性能保护暂停，保留本篇旧快照，取消自动任务 |
| 手动模式显示侧栏、编辑、切换标签、右键打开预览 | 只接入本篇已有快照；无缓存显示刷新提示，不调用宿主渲染 |
| 自动切手动 | 取消待执行任务，保留快照与内容新旧状态 |
| 手动切自动 | 普通待刷新文档安排防抖；受保护文档继续暂停 |
| 立即刷新／失败重试 | 同步取得当前标签最新版本，模式不变；隐藏时也可执行 |
| 隐藏导出 | 同步取得最新快照，不显示 Dock、不改模式 |
| 刷新成功但保护仍有效 | 已同步，同时说明后续自动刷新受性能保护限制 |
| 刷新失败 | 显示原因、重试和复制详情；原快照未被修改时保留旧正文，否则显示错误提示 |

所有自动入口检查模式、保护策略、可见性和文档身份；计时器记录安排时的编辑器及源码版本，
回调再次核对，不能用旧任务立即渲染新标签。同步宿主调用可能处理 Qt 事件，控制器阻止嵌套
渲染，返回后重新核对身份／版本，丢弃过期结果。已经进入宿主的调用不能可靠取消，界面没有
可取消进度。宿主失败时通过调用期间的 `QTextDocument::contentsChanged`、对象存活及文档
身份判断旧正文能否保留；不为每次刷新克隆整个富文本文档。被部分改写的错误结果没有展示版本。

内部 `preview_status.h` 定义 `PreviewStatus`：活动编辑器、展示编辑器、源码版本、展示版本、
文件路径、用户模式、无文档／不支持／待刷新／已同步／暂停／失败状态、保护原因及错误。
`previewStatusChanged()` 通知消费者重新读取这一轻量对象，不读取 Markdown 全文。
源码版本在编辑／路径变化时推进，按文档保存，换标签本身不伪造新版本。Dock 独立展示文件名、
模式及状态；链接错误也使用独立反馈区，不覆盖文件名或刷新状态。

待刷新或失败的快照可继续阅读、复制及在预览内操作；Dock 的 `markPreviewStale()` 保留其
文档身份和展示版本，但取消最新资格及旧位置恢复。控制器在身份、源码版本、展示版本均匹配
且状态已同步时才允许双向滚动，旧快照的两个同步方向均暂停。切换文档立即清除旧点击目标，
只接入该文档的缓存；缓存淘汰或控件销毁后展示版本归零，手动模式下等待用户刷新。
缓存仍最多保留每窗口 3 份原生预览，不新增长期快照存储。

HTML 导出不再根据预览控件可见性选择文档。控制器先同步当前标签，并依据上述编辑器身份、
内容版本和就绪状态判断预览是否可用；内容待刷新时，即使 Dock 已隐藏也会同步调用宿主完成
一次最新渲染。Dock 只允许从身份和版本匹配的原生文档生成 HTML 字节快照，`showMessage()`
会立即使该身份失效，因此备用提示页和错误页不能成为导出数据源。HTML 字节及源文件路径在
打开保存对话框前固定，之后的标签切换不会改变待写入内容。路径选择和文件写入与快照生成
分离，取消直接返回，实际保存继续使用 `QSaveFile` 原子提交。

导出快照采用单文件资源策略。Dock 在固定的 `QTextDocument::toHtml()` 副本中只检查
`<img src>`：相对路径和 `file:` 图片按该文档已经更新的 `baseUrl` 解析，读取成功且 MIME
类型为图片时转换为 Base64 data URL。转换只修改字符串快照，不修改实时预览文档。远程图片
保持原 URL，普通超链接及其指向的本地文件不打包，也不发起网络下载。缺失、不可读或无法
识别为图片的本地资源保留原引用，并在导出 HTML 注释和诊断日志中列明；这种单文件策略避免
资源目录的同名覆盖与失败清理问题，但文件体积会因 Base64 编码增加。

Qt 5.15 会分步排版较长的富文本，期间预览滚动条的范围可能多次变化。Dock 以短计时器合并这些变化，仅在侧栏可见且启用同步滚动时通知控制器重新应用编辑器滚动比例，不会强制一次性排版整篇文档。编辑器侧缓存同时包含编辑器身份及滚动条的 `minimum`、`maximum`、`value`，因此范围变化但数值不变时也会重新计算比例。预览写回编辑器时仅以重入标志跳过插件自己的滚动回调，并更新完整缓存；不能屏蔽滚动条的全部信号，因为宿主 QScintilla 依赖 `valueChanged` 调用 `handleVSb()` 才会滚动正文。

关闭同步滚动后，原生预览刷新不再依赖备用浏览器的恢复逻辑。控制器在调用宿主
`on_updataMarkdown` 前从当前编辑器所属的原生预览捕获阅读比例；渲染成功且编辑器身份、
内容版本仍匹配时，Dock 保存本次恢复目标，并在零延迟恢复及后续富文本布局范围变化后重新
应用该比例。内容缩短时比例会限制在有效范围内；切换编辑器、销毁预览或重新开启同步滚动
会取消旧目标，防止其他文档继承阅读位置。用户使用滚动条、滚轮、键盘或点击正文时也会取消
旧恢复目标，后续窗口调整和布局变化不再把用户拉回旧位置。主题后处理的排队恢复同时核对
用户交互代次。恢复直接写预览滚动条，保留控件自身需要的值变化信号；由于反向同步仅由用户
动作触发，该程序化写入不会反向驱动编辑器。

宿主原生预览仍使用只读 `QTextEdit`，Dock 在其 viewport 上安装局部事件过滤器补足链接激活。
只有鼠标左键在同一链接上按下和释放、移动距离未达到拖动阈值且没有形成文本选区时才处理，
因此文字选择、复制、拖动和滚轮事件继续交给原生控件。纯片段链接在当前原生文档中查找命名
锚点并调整预览滚动条；相对链接使用当前 Markdown 文件目录的 `baseUrl` 解析。可交给系统打开的
协议限制为 `http`、`https`、`mailto` 和 `file`，不支持的协议和系统打开失败会写入诊断日志并在
Dock 文档栏显示反馈。系统 URL 打开函数封装为可替换回调，自动化测试只记录请求，不启动外部
程序。

## 文档样式与主题刷新

Qt 5.15.2 的主渲染链路仍由宿主 `QTextEdit::setMarkdown()` 负责 Markdown 解析，不把浏览器
CSS 当作完整样式保证。插件在宿主生成 `QTextDocument` 后执行一次不重新解析源文本的格式
后处理：控件 palette 负责正文与背景，Qt Markdown 写入的标题级别、引用级别和代码围栏属性
用于设置块格式，原生代码字体属性用于识别行内代码，锚点使用 palette 的链接色，`QTextTable` 使用
边框、单元格留白和表头背景。`markdown.css` 继续服务备用 `QTextBrowser`、HTML 片段及默认
导出样式；它不代表原生 Markdown 支持完整浏览器 CSS 盒模型、选择器或脚本。

首次调用宿主 `on_viewMarkdown` 时，格式后处理发生在宿主初次渲染之后；复用已有原生预览
并调用 `on_updataMarkdown` 时，则在宿主更新返回后再次执行同一入口。因此首次打开、手工刷新
和防抖刷新不会因样式设置时序不同而产生两套结果。Dock 合并处理 `PaletteChange`、
`ApplicationPaletteChange` 和 `StyleChange`，主题变化只更新已有富文本文档和控件 palette，
不会再次读取 Markdown 或调用宿主全文解析。样式变化对当前已同步快照沿用编辑器主导的同步规则；关闭同步滚动或正在阅读旧快照时
恢复该文档的预览滚动比例。零延迟与后续布局恢复同时检查编辑器身份、展示版本、样式更新
代次和用户交互代次，避免将旧任务应用到新标签或覆盖后续主动滚动。

## 保存字体与窗口缩放（REQ-002）

`PreviewController` 保存窗口自己的 `SavedMarkdownFont`、临时缩放 `Z` 和一次打开状态。
首次打开及用户明确隐藏／关闭后重新打开才调用一次适配器，调用前标记本次打开，以合并
菜单动作、右键动作和显示通知。最小化恢复、重复显示、换标签、刷新、主题事件、缓存接入、
恢复字号和导出均不读取新配置。初始化只取得内置默认值；未打开预览直接导出使用该默认值。
不同窗口可以暂时使用不同时间读取的基准。读取失败也结束本次读取，下次重开才重新尝试。

读取模块按 Qt `IniFormat/UserScope` 根目录寻找 `notepad/nddsets.ini` 的已保存 `skinid`，
精确映射 0～17 的主题目录，选择用户 `notepad/userstyle/<主题>/markdown.ini`，文件不存在
才选择宿主进程 `applicationDirPath()/themes/<主题>/markdown.ini`。普通正文键固定为
`Scintilla/Markdown/style0/font`，使用 QSettings 的五项 QStringList 解码，只复用字体族与
整数字号。非 Default 主题缺该键时可用同文件 `defaultfont`；Default 缺该键时采用内置基准。
用户文件整体优先，不按字段合并模板，不读取其他语言、光标样式、编辑器 zoom 或二次叠加 AllGlobal。

路径定位使用随机不存在的相邻组织名，仅取得 QSettings 路径。真实源文件始终由 QFile
只读打开；QSettings 只解析短生命周期私有副本，解析对象先销毁，随后自动删除副本。这样
避免读取对象销毁时冲刷同进程宿主 QSettings 缓存里的待保存值。没有配置轮询、监听、保存
稳定性检测、自动重试、专用文件大小阈值或配置回写。测试不依赖本地宿主库或 build 探针。

正常缺失采用内置默认；文件读取、INI、主题或字体字段失败时，本次基准回到平台默认字体
与 12 pt，不继承上次有效结果。Windows 首选 Courier New，Linux 对照首选 Courier 10 Pitch；
平台字体不存在时用系统默认字体。仅配置字体族不可用且字号有效时保留其字号。结果包含
主题、所选文件、字段来源、读取结果和字体回退标志；日志仅记录简短原因，不输出完整配置
或增加异常界面。代码使用可用等宽字体，正文字体本来等宽时可复用。

Dock 以 `B × Z` 设置 QTextDocument 的正文默认字体与各片段字号，H1～H6 分别乘
2.00、1.75、1.50、1.30、1.15、1.05。标题内代码服从标题比例，其他代码与正文同号。
正文区域的 H1～H6 标题另加 0、12、24、36、48、60 个逻辑像素的左边距，乘以窗口临时缩放 Z；
存在 Qt 引用级别属性的标题叠加引用边距；Qt 未保留该属性的引用内标题仅按标题级别缩进。
列表结构保持不变，普通正文不跟随标题缩进。每次从语义层级
重新计算，主题、刷新和缩放不会累加缩进；不插入空格或修改标题文本。HTML 快照保留此排版。
保留 Markdown 粗体、斜体、删除线、表头强调、链接及等宽代码，不继承宿主正文的强调标志。
字号保留小数，不额外乘 DPI。每次应用都从 B 与 Z 计算绝对值，避免重复放大。
Qt 5.15.2 的系统等宽字体不一定设置 fixedPitch 标志；识别导入器的显式字体属性后，
用片段内部标记保留代码身份，并清除会覆盖目标字体的 FontFamilies／StyleName 属性。
格式操作放在一次 `beginEditBlock()/endEditBlock()` 中合并，避免逐片段触发布局；未改变
文档修订、字体基准、缩放和主题样式的缓存接入跳过重复格式遍历。

原生只读 QTextEdit 的 Ctrl＋滚轮事件在受保护的事件转发中交给原控件处理一次，随后
从其 `document()->defaultFont()` 读取缩放后的正文大小并计算 Z。这是预览临时缩放结果，
不作为宿主字体数据源；空文档、纯标题或纯代码也可读取。步进、方向、分数增量和缩放边界
全部来自原控件。Dock 同步修正标题与代码的比例，通知控制器保存窗口 Z；“恢复宿主字号”
菜单动作将 Z 设为 100%，只恢复本次打开基准，不读取配置、不改变刷新或同步选择。

纯样式操作不调用宿主解析，不推进源码或展示版本，也不改变旧快照状态。缓存重建与
`setMarkdown()` 后重新应用当次 B 与 Z；后台缓存只在接入时更新样式。旧布局恢复任务在
新样式、换文档、用户滚动或控件销毁后失效。HTML 仍导出最新有效内容的固定快照，可携带
该文档字体格式；隐藏导出复用最近基准，不增加字体读取或修改临时缩放。

## 渲染选择

notepad-- v3.8.3 已有 `MarkdownView`，内部使用 `QTextEdit::setMarkdown()`。插件通过 Qt 元对象调用宿主的 `on_viewMarkdown`，再把宿主创建的窗口嵌入 `QDockWidget`，避免复制渲染逻辑，也避免从插件模块调用静态链接的 QScintilla 实现。

## 文件路径与资源

notepad-- 给每个编辑器对象设置了名为 `filePath` 的 Qt 动态属性。插件读取此属性，将 Markdown 文件所在目录设置为原生预览文档的 `baseUrl`，所以 `![图](images/a.png)` 可以从文件目录解析。

控制器通过应用事件过滤器观察本窗口已接入编辑器的 `filePath` 动态属性变化，并保存已处理的
路径用于去重。当前编辑器另存为、重命名或从未命名状态首次保存时，路径变化会推进现有内容
版本并使旧预览失去最新资格，同时更新标题、文件类型和导出状态；自动模式且不受保护时
走防抖，手动模式保留旧快照原资源目录直到刷新。隐藏时显式导出仍取得最新版本。原生预览重新接入时会先把新目录写入
`QTextDocument::baseUrl`，再调用宿主更新内容，因此相对图片不会继续从旧目录解析。事件处理
同时核对编辑器归属，各宿主窗口的控制器不会响应其他窗口的路径变化；后台编辑器只失效缓存，
不更新当前界面，也不启动渲染。

## ABI 与发布

插件入口边界仍包含 Qt 类型、`std::function` 和 `QsciScintilla *`，不是稳定的纯 C ABI。不过插件不再解引用该编辑器指针，也不再链接 QScintilla。因此发布 DLL 必须匹配：

- CPU 架构；
- MSVC 工具链和运行库；
- Qt 主次版本；
- notepad-- v3.8.3 的插件 ABI、窗口对象名和 `on_viewMarkdown` 元对象槽。

插件不再需要 `qmyedit_qt5.lib`。当前实现明确以 notepad-- v3.8.3 为目标；若宿主以后修改插件回调、结构体、窗口对象名或槽函数，需要更新适配层。

## 标题大纲与章节定位（REQ-003）

`heading_index.*` 从已经展示的 `QTextDocument` 标题块提取 H1～H6，记录编辑器身份、内容版本、
层级、显示文本和预览块位置。控制器在成功渲染后读取同版本源码，按标题顺序核对源行；
代码围栏与缩进代码不作为标题；围栏保留所属引用层级和列表缩进，离开容器时隐式结束，
围栏内部额外的引用／列表标记仍按代码处理。空 ATX 标题按 Qt 的渲染结果不加入候选。
ATX、Setext、中文、重复标题、行内格式和 LF／CRLF／CR
均有固定预期测试。只解析标题片段来核对行内显示文本，不重新渲染全文；任何数量、层级或文本
不一致都会使该快照的源码目标失效，预览大纲仍可使用。复杂或无法确认的语法明确反馈，
不按标题文字搜索首个匹配项，不使用比例作为标题映射。

`HeadingOutline` 维护标题树、当前章节标记和窗口内的展开状态。树的层级来自最近更浅标题；
位置标识不跨渲染复用。展开状态只按同文档的层级、文本及同名出现次序恢复，文档销毁后清除。
正文滚动合并为 32 ms 更新；最近标题位置通过有序索引查找，不重建索引。当前章节以视口顶部
最近前置标题判定，首标题前无标记，文末归属最后一章。当前标记与键盘选择独立；折叠祖先
用空心标记提示其后代包含当前章节，不自动展开、抢焦点或滚动大纲。

Dock 使用水平 `QSplitter` 在大纲与预览正文之间分配宽度，鼠标拖动分隔条即可调宽；
设置按钮提供显隐和左右方向。默认左侧显示并展开全部标题；设置只保存在所属窗口中。方向、宽度、
显隐变化保留当前阅读位置，不读源码、不重建标题索引、不修改刷新模式或临时缩放。
“正文待刷新”直接比较活动编辑器、展示编辑器及实际源码／展示版本，不根据手动模式或保护
状态推断。无快照和无标题使用不同空状态，切换文档立即使旧交互失效。

源码能力经 `HostAdapter::readSource()` 与 `navigateSource()` 接入，其默认实现位于
`source_navigation.*`。固定 notepad-- 基线注册的 Qt 无障碍文本接口提供缓冲区读取、
字符位置反查和 `scrollToSubstring()`；通过元对象调用现有 `ensureLineVisible(int)` 槽。
插件仍只链接 Qt，不链接 QScintilla，不修改宿主或入口 ABI，不模拟键盘或发送原生窗口消息。
该基线的 `characterRect()` 传参存在缺陷，因此用 `offsetAtPoint()` 反查源码视口顶部，
以至多 32 次有界搜索定位目标，不依赖预览比例。源行从 0 开始，accessibility 偏移是 Unicode
字符计数，`QString` 索引是 UTF-16，Scintilla 内部是字节；这三种单位不能混用。
目标在源码折叠内时只展开必要祖先，使标题可见；不改变文本、光标、选区或修改标记。

控制器只接受自身缓存中的标题记录，显式导航即使连续同步关闭也可执行。旧快照只定位预览并
提示刷新；源码读取／定位不可用或映射不可靠时明确反馈。每个宿主调用及滚动步骤前后核对
对象存活和当前文档／版本。源码读取期间发生重入修改时，已经变动的渲染结果不能冒充旧快照。
主动目标在 Dock 内保留，优先于比例同步、兼容轮询和位置恢复；源码范围变更合并后重新定位。
下一次编辑器用户滚动在同步开启且快照最新时释放目标，恢复编辑器主导。程序化写入只阻止
插件自己的反馈，保留宿主 `valueChanged -> handleVSb` 信号链。

## 预览内搜索（REQ-004）

`PreviewSearch` 是 Dock 内按窗口持有的搜索栏，控制器通过 `setSearchStatus()` 提供
已接受的展示编辑器、展示版本和源码新旧状态。只有当前文档的有效原生快照可以绑定；
提示页、错误页和换标签前的旧目标立即失效。手动模式下继续搜索本篇已展示的旧快照，
不读取源码、不调用宿主渲染，也不驱动源码导航。

匹配按 `QTextBlock` 内的渲染文字执行，忽略富文本片段边界，保留中文、标点和空白；
不跨段落、表格单元格、显式换行或图片对象，按从前到后的非重叠字面命中计数。
默认不区分大小写，使用 Qt 的逐 UTF-16 字符大小写折叠；不提供语言相关等价转换、
正则、整词或规范化搜索。查询输入框沿用 QLineEdit 的 32767 字符上限。
粘贴、拖入和输入的多行查询先取第一行并提示；输入法组合文本不被 Enter／Esc 导航截走。

查询变更防抖 75 ms；KMP 匹配每次只提取最多 4096 个字符，单批以 4 ms 或 65536
字符为让出事件循环的目标，批间间隔 5 ms。不复制整篇纯文本，不为每个命中保存
`QTextCursor`；全部结果只保存整数位置，空间随命中数线性增长。结果完整计算后显示
精确总数并启用前后导航；计算中显示“已找到 N · 计算中”，不将部分计数当作最终总数。
时间预算在块／提取片段之间检查，单片段及 Qt 布局可能超出 4 ms，实测边界单列记录。

临时高亮使用 `QTextEdit::ExtraSelection`，只维护可见阅读范围及当前项，最多 256 个；
界面明确说明高亮范围受限，完整结果仍全部可导航。当前项使用主题选中色，其他项使用
半透明背景。仅移除带搜索标记的高亮，保留其他显示选区；不改变正文格式、原文本选区
或 `QTextDocument::toHtml()`。字号和主题后处理有明确的格式更新边界，更新文档修订号
而不误判为正文替换。高亮更新防重入，避免布局触发滚动后递归建立高亮。可见结果范围、当前项、代次和配色未变化时跳过
重复建立选区；视口尺寸变化通过 Dock 的布局计时器合并后重新计算可见高亮，
即使滚动值未变化也会更新，不重新扫描全文或改变查询代次。没有命中时不查询文档几何位置。原生文档还在惰性排版时，只读取
末块已有 QTextLayout 的行数来判断就绪，不调用会推进排版的命中测试或 documentSize。
计数继续分批执行，界面提示“正文排版中，高亮稍后显示”，每 50 ms 校验一次；隐藏、
关闭、换文档和新查询都会使旧检查失效。排版就绪后才创建高亮，避免搜索强制提前完成
原生长文档布局。原生排版自身的事件耗时与已显示快照搜索分别测量。

搜索代次、编辑器 QPointer、文档对象、展示版本与文档修订号共同约束延迟任务。
`contentsChange` 中同步失效结果，延迟到 Qt 正文替换退出后清理显示高亮，避免在
不完整的布局中重新进入 QTextEdit。文档销毁则在 destroyed 信号中同步清理：此时私有
文档数据仍存活，必须在 Qt 遗留的显示选区游标失效前移除它们。关闭搜索清空查询和大小写状态；隐藏 Dock 保留
查询、停止计算，重开后重新校验快照。销毁时先停止任务、断开连接和清理高亮。

首次查询只选择首个结果，输入与刷新重算不主动滚动。刷新前保存当前命中在段内的前后
各 24 个字符上下文；新结果中优先选择上下文一致、距离原位置最近的一项，无法对应则
回到首项。保存的是上下文线索，新快照仍必须重新计算全部坐标。
“上一处／下一处”发出带身份和版本的预览定位请求，复用大纲的
`navigatePreviewPosition()`、延迟布局恢复与滚动仲裁。该入口清除先前的大纲源码目标，
搜索请求同时携带命中长度；在保持纵向导航目标的同时，按需调整横向滚动，使宽表格中的
命中范围进入视口。范围宽于视口时优先显示起点，不改变原文本选区；延迟布局后重新校验
快照并恢复目标；用户主动操作横向滚动条会取消旧目标，后续布局不会将其拉回。
搜索本身只定位预览；用户后续滚动继续按既有规则恢复同步主导权。

## 代码块阅读与复制（REQ-007）

`code_block_index.*` 保存带编辑器身份、展示版本和块序号的代码记录。成功渲染后，控制器
通过已有 `HostAdapter::readSource()` 一次读取同版本源码，与标题映射共用读取结果；即使
没有标题也读取，以识别 Qt 不产生显示块的空围栏。调用返回后重新核对对象和版本，重入
变更使本次结果失效。源码只在索引构建期间使用；缓存保留代码内容而非整篇源码，随最多
三份原生预览保存，淘汰和失败失效时释放。后台编辑、复制和显示设置不读取源码。

提取支持普通围栏、缩进代码、常见引用／列表容器及容器隐式结束。去掉 Markdown 结构
缩进，保留代码空格、Tab、内部空行、特殊字符及内容自身的尾部换行，统一 CRLF／CR 为
逻辑 LF。闭合围栏前内容行的终止换行保留；没有终止换行的未闭合围栏不补换行；空围栏为
空字符串；缩进代码块外的尾部空行不纳入代码。语言采用声明首个空白分隔标识，未知值不猜测。

Qt 5.15 将行首 Tab 展开为空格，并在非空代码块末尾生成一个空段落；源文本与用于核对的
显示文本分别保存于临时提取记录。核对全部代码段落的顺序、文字、语言、围栏类型和块内
连续位置，全部一致后才允许复制。不会用显示段落拼接作为复制结果。复杂或无法确认的
语法（例如含原始 HTML 块）保守禁用本快照的代码复制；不猜测空围栏或相邻块的身份。

`CodeBlockTools` 管理附着在预览 viewport 上的代码块页头：左侧淡色语言，右侧 24×24
逻辑像素的复制图标，支持键盘焦点。没有顶部选择栏。每个按钮绑定当前快照中的块序号与
代次；成功短暂变为勾号，失败为提示图标，旧快照和失败原因用 tooltip／无障碍描述反馈。
正文拖选区域不覆盖按钮，右键菜单保留直接复制；Qt 未渲染的空围栏通过右键菜单访问。

每块第一段保留 28 逻辑像素的页头空间，位置变化不修改字符坐标或复制文本。Qt 忽略首段
顶部间距，因此文首代码另在根 frame 保存原间距并增加页头空间；重渲染普通首段时恢复。
格式标记保存原间距，主题／字号／缓存接入按绝对值应用，已知格式更新同步搜索与样式缓存
的修订号。HTML 导出仅在含页头标记时克隆文档并恢复原间距，不导出图标、标签或显示间距。

仅为当前可见代码块创建页头控件，离开视口即隐藏、禁用并释放；长文档不常驻整篇按钮。
滚动、窗口大小和布局变化合并为 16 ms 的页头定位，按钮保持在可见预览右边缘；隐藏的
预览不轮询，不强制完成尚未就绪的长文档布局。换文档或销毁立即隐藏、禁用旧页头并延迟
释放；菜单和按钮回调核对代次。成功反馈不改正文尺寸。

复制写入有可注入边界，默认写入后读回剪贴板进行校验。写入前再次经控制器核对当前宿主
标签及展示身份，阻止零延迟标签通知尚未处理时使用旧入口。正文变更立即清理记录和菜单；
菜单回调还核对代次。主题／字号处理通过明确格式更新边界保留代码记录；窗口、文档及
编辑器销毁时断开连接，剪贴板回调重入也不能恢复旧反馈。

设置中的“代码块视觉自动换行”默认开启，关闭时仅代码段设置 `nonBreakableLines`，
预览水平滚动条按需显示。普通段落保持原换行策略；宽代码与表格共享预览水平滚动范围，
不提供块内独立水平滚动。此样式经原有主题／字体／刷新路径应用，不重新解析 Markdown。
专属偏好使用 QSettings 用户级 INI，组织 `markdownviewdd`、应用 `reading`，键
`codeBlocks/visualWrap`。各窗口加载自己的初值；修改立即作用于本窗口并保存，新窗口和
重启后读取最后保存值，已打开其他窗口不联动。保存失败有明确反馈，不改宿主配置或 ABI。
