# 预览面板界面统一与浮动窗口重新停靠方案

- 日期：2026-09-15。
- 状态：已实施，自动化及云端验证见[验证记录](../verification-ui-redesign-2026-09-15.md)，真实宿主验收待完成。
- 本次交付：依照本方案实施插件界面改造并保留分层验证证据。
- 目录沿用需求指定的 `docs/requirments/` 拼写。

## 1. 背景与目标

当前预览面板从上到下包含“Markdown 预览”停靠标题、文件名与长度、工具栏、刷新状态及正文。
标题与文档信息分占两行，状态信息继续占据正文上方空间。工具栏混用刷新模式下拉框、
普通文字按钮、同步滚动开关和设置菜单按钮，视觉与交互反馈缺乏统一规则。
用户另外反馈：窗口浮动后，没有明确的按钮可以将其重新停靠回主窗口。

设计目标：

1. 合并标题信息，让正常状态下的顶部只保留一行标题和一行工具栏。
2. 统一刷新、同步滚动、查找、设置及窗口控制的图标、尺寸、间距和状态反馈。
3. 减少常驻辅助信息，让正文成为视觉中心，同时明确提示旧快照、性能保护和失败。
4. 提供位置固定、可以往返操作的“浮动／停靠回主窗口”按钮。
5. 保持桌面编辑器的简洁风格，适配宿主明暗主题、窄面板和高 DPI。

## 2. 范围与既有行为约束

本方案覆盖标题栏、工具栏、状态提示、查找栏、大纲、设置菜单和代码复制按钮的视觉一致性，
以及浮动窗口重新停靠行为。

刷新调度、文档身份和版本校验、原生渲染、搜索匹配、导航仲裁、同步滚动门控、HTML 导出、
代码复制与各窗口隔离继续遵循既有语义。视觉布局变化不应额外触发 Markdown 解析或改变
刷新模式。偏好保存沿用已有作用域，不因界面重设计扩大为全局联动。

不修改宿主源码，不改变插件 ABI。具体 Qt 标题栏实现方式在实施阶段结合真实宿主验证确定；
本方案要求的是可见入口、行为与验收结果。

## 3. 整体布局

标准宽度、停靠状态示意如下。方括号代表操作区域，实际使用统一的线性图标。

```text
┌─────────────────────────────────────────────────────────┐
│ 预览  preview-demo.md                    [浮动] [关闭]   │
├─────────────────────────────────────────────────────────┤
│ [刷新图标│自动 ▾] [同步滚动]               [查找] [设置] │
├─────────────────────────────────────────────────────────┤
│ 查找栏：仅在打开查找时显示                               │
│ 异常提示：仅在需要处理时显示                             │
├────────────┬────────────────────────────────────────────┤
│ 大纲       │ 正文                                       │
│            │                                            │
├────────────┴────────────────────────────────────────────┤
│ 已更新                                                  │
└─────────────────────────────────────────────────────────┘
```

查找栏和异常提示在未启用时不预留空白。正常状态下工具栏之后直接进入正文与大纲。
浮动时将右上角“浮动”替换为“停靠回主窗口”。浮动系统标题与插件标题应协调显示，
避免再出现两行重复的“预览＋文件名”。

## 4. 标题与文档身份

- 标题简化为“预览”，文件名在同一行用次要文字颜色显示。
- 删除独立文件名行；“长度 ××”不再常驻，移入详情。
- 文件名过长时省略，悬停可查看完整路径；保留获取或复制完整文档信息的途径。
- 无活动文档时标题只显示“预览”，正文提示打开 Markdown 文档。
- 未命名文档显示“未命名文档”；切换、保存及改名后更新对应文档身份。
- 标题空白区域保留拖动能力，按钮点击不得误触拖动。
- 保留文件名是为了识别预览归属，尤其适用于浮动和多窗口场景。

## 5. 工具栏

### 5.1 排列与分组

左侧为刷新组合控件、同步滚动；右侧为查找与设置。组内紧凑、组间留白，
不让每个按钮都具有同等强烈的边框或背景。

### 5.2 刷新组合控件

- 左侧刷新图标执行“立即刷新”，悬停提示“立即刷新当前文档”。
- 右侧显示“自动 ▾”或“手动 ▾”，点击打开“自动刷新／手动刷新”互斥菜单。
- 两部分共享外框，点击区域独立，键盘可分别访问，菜单明确标记当前选项。
- 自动模式下仍可立即刷新；点击立即刷新不改变当前模式。
- 性能保护暂停自动更新时，仍显示用户选择的“自动”，通过状态提示解释暂停原因。
- 工具栏与宿主插件菜单保持状态同步，继续按所属窗口隔离。

### 5.3 同步滚动

- 使用同系列的联动图标，标准宽度显示“图标＋同步滚动”。
- 开启时使用淡强调色背景与选中边界，关闭时使用普通中性样式。
- 窄面板可以仅显示图标，悬停与无障碍描述明确说明名称及开关状态。
- 开关选择与实际能否同步应区分：旧快照等情况下继续遵循既有同步门控，
  不能仅因按钮处于选中状态就绕过版本校验。

### 5.4 查找与设置

- 右侧统一采用图标按钮，查找使用放大镜，设置使用统一风格的设置图标。
- 提示名称分别为“在预览中查找”和“预览设置”；查找提示包含已有快捷键 Ctrl+F。
- 查找入口展开查找栏；设置入口打开菜单，菜单打开状态有一致反馈。
- 快捷键归属继续遵循当前焦点与所属宿主窗口规则。

## 6. 视觉规范

以下为初始设计规格，均按逻辑像素理解；实施时根据宿主字体和 DPI 微调，并记录最终值。

| 项目 | 设计要求 |
| --- | --- |
| 图标 | 同一套 16 像素线性图标，统一线宽；不混用字符图标、彩色图标和不同素材风格 |
| 按钮高度 | 约 28–30 像素，图标居中，点击区域不小于可见按钮区域 |
| 圆角 | 约 4–6 像素，整个面板采用一致规则 |
| 间距 | 组内约 4 像素，组间约 12 像素，工具栏左右约 10–12 像素 |
| 颜色 | 跟随宿主明暗主题，强调色用于选中、焦点及当前定位 |
| 边界 | 使用细分隔线及轻微背景差异，减少厚边框与大面积按钮底色 |
| 字体 | 工具区域跟随宿主界面字体，正文继续使用阅读字体设置 |
| 状态 | 统一普通、悬停、按下、选中、禁用和键盘焦点样式 |

所有按钮具备明确的名称、提示及键盘可访问性；选中和错误状态不能只通过颜色区分。
高 DPI 下图标清晰、文字完整、焦点轮廓可见。禁用原因应可被理解，不能仅把按钮变灰。

## 7. 状态、错误与短暂反馈

正常刷新状态移到底部轻量状态栏，避免在正文上方常驻多行状态和诊断按钮。

| 状态 | 展示要求 |
| --- | --- |
| 已更新 | 底部弱化显示“已更新” |
| 待刷新且有旧快照 | 显示“待刷新 · 当前显示旧内容” |
| 尚无有效预览 | 正文提示通过刷新生成预览，提供明确操作入口 |
| 性能保护暂停 | 明确说明“自动刷新已暂停”，提供刷新入口；详情说明原因 |
| 刷新失败 | 正文上方按需出现紧凑提示条，提供“重试”和“详情” |

- 有旧快照时，刷新失败仍保留可读内容，并说明其并非最新版本。
- 详情承载完整原因、诊断信息和复制详情操作；“复制详情”不常驻占用正常工具区域。
- 底部简短状态与顶部异常提示避免重复展示同一段长文本。
- 必须处理的错误持续可见，不能只放在悬停提示里或过早自动消失。
- 复制成功等短暂反馈优先在操作附近或底部显示，不改变正文尺寸。
- 定位及链接失败等反馈按其重要性展示，避免频繁增加顶部行数、挤动正文。

## 8. 查找栏、大纲、设置和代码复制

### 8.1 查找栏

- 默认收起，打开后紧贴工具栏下方。
- 输入框、匹配计数、前后跳转、大小写选项和关闭按钮采用统一尺寸与间距。
- 保留现有搜索能力及计算中、无命中、旧快照等提示，不因精简样式删除必要状态。
- 保留 Esc、输入法组合输入、关闭清理和焦点返回等既有行为。
- 窄面板优先保证输入与主要操作可用，允许必要布局调整，不裁切控件。

### 8.2 大纲

- 采用轻量侧栏，标题弱化、层级缩进一致、当前条目淡色高亮。
- 保留用户选择、当前定位和折叠状态之间的区别，以及既有拖动分隔条能力。
- 面板过窄时临时收起大纲，设置入口仍可用；宽度恢复后遵循用户原有选择。
- 临时收起不覆盖用户显隐偏好，左右位置选择不变。
- 具体收起阈值按按钮最小宽度和正文可读宽度在实施阶段确定，避免缩放时反复切换。

### 8.3 设置菜单

按功能分组，初始结构为：

```text
大纲
  ✓ 显示大纲
  位置  → 左侧 / 右侧（互斥）
──────────────────────────
阅读
  ✓ 代码块自动换行
```

简化菜单文字，将“视觉换行、不改变代码内容”等说明移到提示。
保持现有设置作用域与保存行为；隐藏大纲时仍可选择其恢复后的显示位置。

### 8.4 代码复制

复制按钮采用相同图标体系和悬停、焦点、禁用及成功反馈规则。
保留代码块附着位置、语言标签、正文选择、旧快照校验和复制内容语义。
成功提示不改变代码块尺寸，导出 HTML 不包含界面控件和状态装饰。

## 9. 浮动与重新停靠

### 9.1 固定入口

标题栏右侧、关闭按钮之前固定提供窗口状态切换按钮。

| 当前状态 | 按钮及悬停提示 | 点击结果 |
| --- | --- | --- |
| 停靠 | 浮动图标；“浮动窗口” | 将预览变为独立窗口 |
| 浮动 | 停靠图标；“停靠回主窗口” | 将预览放回所属主窗口 |

按钮在浮动后仍必须可见，无需依赖拖拽或双击才能返回。
图标随实际窗口状态更新；通过拖动等其他途径改变状态后也应保持正确。
系统窗口装饰不得遮挡或替代该显式返回入口。

### 9.2 返回位置与归属

- 优先恢复本次会话中浮动前的左侧或右侧停靠位置；无历史位置时默认右侧。
- 多个宿主窗口同时打开时，只能返回该预览所属的主窗口。
- 切换保留当前文档、阅读位置、查找内容、大纲设置、刷新模式及同步滚动选择。
- 窗口尺寸变化可引发布局调整，但不得因此强制刷新、跳到文首或清空搜索。
- 位置恢复继续遵循既有导航和滚动仲裁，用户主动操作不能被旧的延迟任务覆盖。
- 不要求新增跨进程保存窗口布局的机制。

### 9.3 关闭与边界情况

- “关闭”隐藏预览，“停靠”放回主窗口，两者使用不同图标和明确提示。
- 浮动状态只保留一套清晰的有效关闭入口，避免系统标题和自定义标题重复堆叠。
- 保留拖动、停靠和浮动能力，同时验证按钮附近拖动不误触。
- 既有非 QMainWindow 的浮动降级场景若没有有效停靠目标，不显示可成功返回的假象；
  返回按钮禁用并说明原因，关闭入口仍可用。
- 所属主窗口销毁后不留下孤立窗口或可访问已销毁对象的按钮回调。

## 10. 宽度与主题适配

- 标准宽度采用“同步滚动”图标加文字，查找与设置保持图标形式。
- 窄面板先省略文件名，再隐藏可省略的按钮文字；刷新模式仍保持可辨认。
- 保证刷新、模式切换、同步、查找、设置、停靠返回和关闭入口可访问。
- 必要时调整查找栏布局并临时收起大纲，不以压缩正文到不可读或裁切按钮解决空间问题。
- 明暗主题、宿主字体变化、100%／125%／150%／200% 缩放，以及跨 DPI 屏幕移动均需检查。
- 切换主题后更新图标、文字、背景、分隔线、菜单和焦点样式，避免局部残留旧主题。

## 11. 后续实施组织

1. 建立统一的按钮、图标和主题状态规则。
2. 合并文档标题，完成浮动／停靠返回及标题装饰协调。
3. 重排工具栏，接入刷新组合控件并保持菜单状态同步。
4. 调整状态与错误信息位置，统一查找栏、大纲、设置和复制按钮样式。
5. 完成窄面板、键盘、主题和 DPI 适配，执行回归并保存截图。

主要涉及 Dock 与相应 UI 组件；窗口归属和刷新语义继续由现有控制器边界维护。
如实施改变组件关系或宿主集成方式，同步更新架构及对应专项文档。
会话中的交互草案用于表达布局和视觉方向，本文为仓库内完整需求依据，
不依赖本机会话路径或草案模拟交互来定义产品功能。

## 12. 验收标准

### 12.1 界面验收

- [ ] 正常顶部只有一行标题和一行工具栏，没有独立文件名／长度行。
- [ ] 浮动时没有重复的预览标题，返回按钮始终可见。
- [ ] 所有工具按钮图标、尺寸、间距和状态反馈一致。
- [ ] 当前刷新模式、同步滚动选择及旧内容状态均可辨认。
- [ ] 正常状态信息位于底部；失败可直接重试并访问完整详情。
- [ ] 查找、大纲、设置和代码复制符合统一风格，既有功能入口完整。
- [ ] 长文件名、窄面板、明暗主题及高 DPI 下无遮挡、裁切或难以辨认的状态。
- [ ] 全部操作可以通过键盘访问，焦点可见，图标按钮名称与提示准确。

### 12.2 行为回归

- [ ] 自动／手动切换、立即刷新和性能保护保持原语义，菜单与工具栏一致。
- [ ] 左侧停靠→浮动→按钮返回左侧，右侧同理；无历史位置时返回右侧。
- [ ] 拖动等其他方式改变停靠状态后，按钮图标和提示立即反映实际状态。
- [ ] 浮动／停靠往返不额外解析正文，不丢失文档、阅读位置、查询或大纲设置。
- [ ] 查找栏展开、旧快照、刷新失败及大纲临时收起时均可正确往返停靠。
- [ ] 关闭仅隐藏预览；重新显示后仍能正常使用浮动和停靠按钮。
- [ ] 两个宿主窗口分别操作互不影响；关闭所属主窗口后无残留浮动窗口。
- [ ] 非标准宿主降级和窗口销毁路径无无效返回动作或悬空访问。
- [ ] 搜索、导航、复制、主题和导出回归通过，HTML 无新增 UI 装饰。

### 12.3 验证与证据要求

实施阶段应按[测试指南](../testing.md)运行相关 Qt 行为回归和 Windows Release 构建，
并在[兼容性基线](../host-compatibility.md)的真实 notepad-- x64 宿主中完成手工验证。
自动化重点验证状态转换、窗口归属、阅读状态保留与销毁行为；截图和真实宿主操作验证
标题装饰、图标辨识、DPI 及交互体验。模拟测试成功不能替代真实宿主验收。

保存停靠、浮动、返回后、窄面板、查找展开、错误提示及明暗主题截图；失败时保存诊断日志。
验证记录必须分别列出静态检查、自动化测试、Windows Release 编译、Artifact 校验和真实宿主
测试，并使用 `passed`、`blocked`、`not run` 或 `not verified` 标记。

实施结果以验证记录为准。以上验收清单保留至真实宿主逐项检查后勾选，不以模拟测试代替人工验收。
